# 提出前チェック（機械ゲートの前に自分で読む）

## 内容
- [ ] 見出し・数値・固有名詞はすべてソースから取ったか（無いものを作っていないか）
- [ ] 数値には単位と期間が付いているか
- [ ] 1枚の主役は1つか。4つ以上の箇条書きを1枚に詰めていないか

## 構図と見た目（01_layout の6原則）
- [ ] 設計表に枚数分の構図を書き、**全枚が別の構図**になっているか（03_compositions）
- [ ] 表紙 → 中身 → 締め（一点集中 H）、の順になっているか
- [ ] 見出しはラベルではなく**文**で、強調語（accent）を1つ渡したか
- [ ] 表紙と一点集中以外の全枚に**持ち帰り帯**（takeaway）を置いたか
- [ ] 奥行き（depth）は1枚に1手まで、文字と重なっていないか
- [ ] 文字ブロックは見出し以外 7 個以内か

## レイアウト
- [ ] 外周 0.7in の余白を守っているか。図形が 0〜13.333in / 0〜7.5in の外に出ていないか
- [ ] 文字の枠が「幅×72÷pt」「行数×pt×1.35÷72」の式を満たすか
- [ ] 左揃えの x が同じ値か。右端も揃っているか

## 文字
- [ ] フォントは Meiryo のみか（本文 14pt 以上、注記・ページ番号だけ 11pt 可）
- [ ] 見出しは 26 字以内・1行で帯に収まるか
- [ ] 文字を画像に焼いていないか。図形の中の文字は本物のテキストか

## 色
- [ ] 6色＋Tint/Shade/AccentText（`palette_arg` の9色）以外を使っていないか。色コードを1文字も間違えていないか
- [ ] 画像は依頼があるときだけか。1ページ1枚で、文字と重なっていないか。透過 PNG は cutout で置いたか
- [ ] Accent は1枚に1か所か

## ノート
- [ ] 各スライドのノート欄に発表原稿（150〜250字）が入っているか。空のスライドは失敗

## Gemini Notebook 固有の注意
- [ ] プレビュー画像の日本語が □ に見えても、pptx の中の文字は正常（この環境に日本語フォントが無いだけ）。判断はゲートの結果で行う
- [ ] 画像を生成して入れる場合、生成画像には「Gemini Notebook」の透かしが入る。透かしが困る用途では assets の背景だけを使う
- [ ] 成果物は scratch で作り、ゲートに合格してから out に1回だけコピーする
