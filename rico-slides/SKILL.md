# rico-slides — 見た目の整った、編集できるスライドを作る

## このスキルが守ること（省略禁止）
1. **設計表を先に書く**（枚数・各枚の見出し・強調語・構図・主役・持ち帰り）。書かずに描き始めない。
2. **全枚を別の構図にする**。同じ配置の繰り返しは失敗。
3. **見た目の原則を守る**（`references/01_layout.md`）: 主役1つ／見出しは文で強調語1つ／持ち帰り帯／奥行きは意味のある数字だけ／文字ブロック7個まで／静かに1温度。
4. **配色は10種から1つ（6色＋派生）、フォントは Meiryo、本文は 15pt 以上**。見出しは全角 26 字以内で1行。
5. **配色の指定が無いときは、描き始める前に一覧を出して選んでもらう**（工程0）。勝手に既定で進めない。
6. **描いたら必ず検品ゲートを実行し、NG がゼロになるまで直す**（最大2周）。ゲートを通していない成果物を納品しない。
7. **各スライドのノート欄に発表原稿（150〜250 字）を入れる**。空のスライドがあれば失敗。
8. 数値・固有名詞・見出しは**ソースから取る**。無いものを作らない。

## 工程（この順で）

### 0. 配色とイラストを聞く（指定が無いときだけ・1往復で終わらせる）

依頼文に配色やイラストの手がかりが**無い**ときは、**ここで一度だけ止まって聞く**。設計表も描画もまだ始めない。
**2つとも1回の返信でまとめて聞く**（配色を聞いてから改めてイラストを聞く、のように往復を分けない）。

聞き方は、`references/02_color.md` の10種を**表で出して、番号で選べるようにする**。列は「番号／パレット名／主な色／向いている場面」の4つだけにする（色コードは出さない。長くなって選びにくい）。
表の後に、この2行を必ず添える。

```
番号でお答えください。「おまかせ」と書いていただければ、資料の内容に合うものをこちらで選びます。
この中に無い色がよければ、色の名前かコード（例: 紺、#1F3864、会社のコーポレートカラー）を教えてください。

もうひとつ、イラストを入れますか。
  A 入れない（文字と図だけ。いちばん速くて、印刷にも向きます）
  B 表紙にだけ入れる
  C 表紙と、内容に合うページに入れる
未記入なら A で進めます。イラストはこの場で作るので、隅に Gemini Notebook の透かしが入ります。

以後このチャットでは、同じ配色と同じ方針で作ります。
```

**一覧に無い色を指定されたときの組み方は `references/02_color.md`「一覧に無い色を指定されたとき」に従う。**
色を自分で発明せず、色相の近い 10 種を土台にして Key だけ差し替える。明るすぎる色は Key にできないので、
Accent にまわすか暗くして使い、**どちらにしたかを一言伝える**。

**聞かずに進めてよい場合**（下のどれかに当たれば工程1へ直行する）:
- 依頼文に色・雰囲気の指定がある（「白黒にライム」「落ち着いた赤」「うちのコーポレートカラーで」など）
- 依頼文にイラストの指定がある（「絵を入れて」「画像なしで」「文字だけで」など）。**片方だけ指定があるときは、無いほうだけを聞く**
- 「おまかせ」「どれでもいい」「急ぎで」と言われている
- 同じチャットで既に配色を選んでもらっている（**2回目以降は聞かない**）
- 依頼が修正・追加（「3枚目だけ直して」「1枚足して」）である

**答えが返ってきたら**、その配色とイラストの方針を以後このチャット内で既定にする。「おまかせ」ならソースの内容から選び、**選んだ理由を1文で添える**（例「社内規程なので標準の ink-coral にしました」）。
イラストの答えは `### 画像の作法` に従って形にする（A なら画像を1枚も置かない）。

### 1. 読む
- ソースを読み、伝えたい結論を1文で書く。枚数を決める（指定がなければ 5 枚）。
- `references/03_compositions.md` で枚数ぶんの構図を選ぶ。5〜8 枚なら**重複なし**で「表紙 A → 中身 → 締め H」。10 枚を超えるなら「表紙 A → 目次 M → 章扉 J → 中身 3〜4 枚 → 章扉 J …→ 締め H」で、同じ構図を隣り合わせにしない。数値があれば B・K・G を優先。
- 配色は工程0で決まったものを使う。工程0を飛ばした場合は、依頼文の指定に近いものを `references/02_color.md` の 10 種から選ぶ（手がかりが無ければ ink-coral）。会社指定色があれば Key を差し替える。

### 2. 設計表を書く（チャットに出してから描く）
```
Slide1: A 表紙        「情報セキュリティ 基本の4か条」  強調: 4か条
Slide2: D チェック    「情報は4つに分類して扱う」      強調: 4つ   主役: 4項目   持ち帰り: 自分が扱う情報の区分を先に確かめる
Slide3: E 横フロー    「権限は、仕事に必要な分だけ」    強調: 必要な分だけ  主役: 3段階  持ち帰り: 異動・退職から5営業日以内に見直す
Slide4: F タイムライン「事故の疑いは、24時間以内に上へ」強調: 24時間以内  主役: 4点（強調1点）持ち帰り: 怒られるかも、より先に報告
Slide5: H 一点集中    「持ち出さない。迷ったら、すぐ報告する。」 強調: すぐ報告する
```
- 見出しは「言いたいことを文で」。26 字以内。強調語は意味を担う1語（数字・禁止・期限など）。
- 持ち帰りは「だから何」を1文で。
- 1枚の文字量は `references/01_layout.md` の式で確認する。入らないなら**言葉を削る**。

### 3. 描く（python-pptx）
- `scripts/slide_helpers.py` の `Deck` を使う。骨格は `cover` / `slide` / `takeaway` / `section`、構図は `hero_number` / `two_column` / `checklist` / `flow` / `timeline` / `bars` / `statement` / `quad` / `kpi3` / `table` / `agenda`。**この名前以外の関数は無い**（`title_slide` や `headband_slide` は存在しない）。使う前に `slide_helpers.py` の docstring を読む。
- 本文スライドは必ず `d.slide(見出し, accent=強調語, eyebrow=章名, notes=原稿)` → 構図の関数 → `d.takeaway(s, 一文)` の3点セット。accent を省略しない。
- 座標はヘルパーに任せる。自分で図形を置くときは外周 0.7in を守り、パレット外の色を使わない。
- 具象物（人・建物・食べ物）を図形で作らない。絵が要るときは画像を置く（下の「画像の作法」）。

### 画像の作法（工程0で B か C を選ばれたとき、または依頼に「画像を使う」「表紙に絵を」とあるときだけ。無断で足さない）
- 置き場所は3つ: 表紙 `cover(image=…)` / 章扉 `section(image=…)` / 本文 `picture_text()`。装飾のために画像を散らさない。
- **写真・不透明イラスト**は `image=`（枠いっぱいにトリミング）。**背景透過 PNG の切り抜き**は `cutout=`（Key や Surface の地に浮かべる）。ユーザーが透過 PNG を渡してきたら cutout を使う。
- 自分で生成するときは、パレットの色で指示する。文字・ロゴ・透かし風の装飾を入れさせない:
  「フラットな平面イラスト、単色ベタ塗り、余白広め、文字なし、ロゴなし、光沢・3D・写実は禁止。背景色 #<Surface>、主色 #<Key>、差し色 #<Accent> の3色だけ。題材: <そのページの主役>」
- この環境で生成した画像には右下に「Gemini Notebook」の透かしが入る。**`slide_helpers` が画像の下端 6% を自動で切り落とすので、置いただけで透かしは消える**（`picture_fill` / `picture_fit` の両方で効く）。
  透かしが残るほど大きい場合は `Deck(watermark_crop=0.10)` のように割合を上げる。下を切りたくないときは `0.0`。
  切っても消えない・絵の主役まで切れてしまうときは、ユーザーが用意した画像（ソースにアップロード）を使う。
- 画像は1ページ1枚。文字と重ねない。検品ゲートは画像の上の文字を G4（重なり）で落とす。
- ファイルは `/workspace/scratch/` に保存する。

最小コード:
```python
import sys; sys.path.insert(0, "<展開先>/rico-slides/scripts")
from slide_helpers import Deck, palette_arg
d = Deck(palette="ink-coral")
d.cover("情報セキュリティ\n基本の4か条", "新入社員研修", eyebrow="総務部", accent_word="4か条", notes="…")
s = d.slide("情報は4つに分類して扱う", accent="4つ", eyebrow="第3条", notes="…", depth="numeral:4")
d.checklist(s, ["極秘|経営判断に直結する情報", "秘|人事・契約・顧客の情報", "社外秘|社内限定の資料", "公開|誰が見てもよい情報"])
d.takeaway(s, "自分が扱う情報が、どの区分かを先に確かめる")
s = d.slide(None, eyebrow="まとめ", notes="…")
d.statement(s, "持ち出さない。\n迷ったら、すぐ報告する。", accent="すぐ報告する")
d.deliver("/workspace/scratch/deck.pptx")   # save＋自動検品。NG ゼロのときだけ /workspace/out にコピーされる
```
- `save()` は保存のたびに検品ゲートを自動実行して結果を印字する（戻り値 = NG 件数）。`deliver()` は NG ゼロのときだけ out にコピーする。
- 見出しの `accent=` は**見出しの中にある語**を渡す。無い語を渡すとエラーで止まる（素の見出しに逃げない）。

### 4. 検品（必須）
```
python <展開先>/rico-slides/scripts/pptx_slide_gate.py /workspace/scratch/deck.pptx \
  --palette <palette_arg(d.c) の出力> --font Meiryo --headline-max 26 --min-font 14
```
- 結果の NG を1件ずつ直し、再実行する。2周で消えない NG は、内容を削るか構図を変える。
- 出力（NG 件数と内訳）は納品の報告に**そのまま貼る**。「合格」と自称しない。

### 5. 納品
- `d.deliver()` が NG ゼロのときだけ `/workspace/out/` にコピーする（中間ファイルは out に置かない）。NG が残る間はコピーされない。
- 報告に書くこと: 設計表、パレット名、ゲートの結果（原文）、ノートの有無。
- この環境のプレビュー画像は日本語が □ に見えることがある。pptx の文字は正常なので、判断はゲートの結果で行う（`references/04_checklist.md`）。

## やらないこと
- 4つ以上の箇条書きを1枚に詰める（チェックリストか比例バーに変換する）。
- 影・グラデーション・3D・絵文字・文字の画像化。
- 紺の帯＋白カード＋番号リストを全枚で繰り返す「管理画面のようなスライド」。
- パレット外の色。色コードの打ち間違い（出力前に全色を照合する）。
- ゲート未実行での納品。ゲート結果の要約や言い換え。
